# Scientific QC standard

The sole review report is `docs/pset_qc.html`, generated by `pixi run qc` from the final serialized PSet. Internal small fixtures are software tests and must not be published as alternative QC reports.

Every report must describe the measurement and response scale, sample/compound/dose coverage, missingness, fit quality and molecular coverage; explore the actual response distributions and representative curves; and include feasible, explicitly exploratory common analyses. Optimizer success and object validity alone are insufficient.

Where a legitimate published reference exists, match identifiers, technical contexts, orientation, units, response transforms and metric definitions before comparison. Report paired counts and unpaired missingness, Pearson and Spearman correlations, identity plots, difference-versus-mean plots, systematic bias and named outliers. Include all-pair and justified sensitivity analyses, with denominator and selection rules. Correlation is not agreement. Distinguish observed from fitted response/synergy, and derived-from-published-parameters from directly published metrics. If no comparable reference is available, document the gap instead of manufacturing a comparator.

Reports must read existing artifacts without refitting expensive curves, acquiring data, or changing scientific values. Export supporting numeric tables and inspect rendered plots. Record package/source versions and limitations. Reference examples are CCLE Drug QC, Nikta's GDSC2 metric QC and Nasim's ALMANAC QC; port their intent, not stale schema assumptions or unsupported fixes. Human case-study answer keys remain separate from benchmark inputs.

Run `pixi run test-qc` for lightweight numeric helper checks. These tests have no alternate report deliverable. `docs/qc-data/` contains generated supporting TSV/PNG files and is excluded from Git; the report can be regenerated from the final object and recorded reference inputs.

### Tested IC50 convention

At the tested PharmacoGx MCP commit `28c58707eece80086bee75d8ef0e8afae96389ca`, `computeIC50()` defaults to `reference="relative"`. The existing pipelines use that default, so stored IC50 fields represent relative half-effect, not automatically 50% absolute viability. EC50 comparisons in the scientific QC use the fitted location parameter directly. Historical peer IC50 values must be treated as diagnostic comparisons unless their reference convention and model limits are established. No active fitting code or checkpoint signature was changed to add this documentation.

Where source data explicitly label single-agent versus combination wells, use those labels and audit incomplete partner annotations. An absent drug identifier must not silently turn a combination into a monotherapy control. Preserve incomplete source observations with clear flags, exclude unsupported contexts from derived estimates, and inspect individual agreement outliers even when the overall correlation is high. The Anchor source-tag regression is a concrete example of why this check belongs in scientific QC.

CoreGx constructor keys must preserve every observed dose and replicate dimension in the row/column layout. The entity-only-key collapse has been reproduced on the intended PR178 dependency pair as well as another installed CoreGx build. Require source-to-object row-count, key-uniqueness and exact per-column measurement checks through the saved artifact's public raw accessor; `validObject()` alone is insufficient.

Optimizer-reported fit R² and returned-curve fit quality must be distinguished. The pinned PR178 implementation computes its variance-based R² before asymptote truncation. Evaluate stored parameters against the actual transformed modeling inputs without refitting, preserve the reported value, check dose support, and include a bias-sensitive SSE/SST diagnostic. Treat flat-response R² as undefined and retain negative values.
